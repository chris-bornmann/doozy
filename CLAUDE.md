# Development Guidelines

## Code Style

- Prefer clear, easy-to-understand code over concise code. Readability and maintainability come first.
- Add comments to any code that might be difficult to understand at a glance.
- Prefix the name of "private" functions with an underscore (_).
- In a function definition, put each function parameter on its own line.
- In a function definition, Put the closing parenthesis and return type on its own line.

## Testing

- Aim for high unit test coverage.
- Every test should assert something meaningful. Tests that exist only to increase coverage numbers are not useful.
